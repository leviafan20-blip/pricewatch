## Обнаруженная и исправленная проблема

Команда тестов из первоначальных README и runbook наследовала
`DJANGO_SETTINGS_MODULE=config.settings.local` из контейнера. Эта переменная
имеет приоритет над настройкой Pytest в `pyproject.toml`.

Инструкция исправлена и проверена:

```powershell
docker compose exec web python -m pytest --ds=config.settings.test --cov=apps --cov-report=term-missing
```

Изменять код приложения, Dockerfile, Compose или миграции для запуска не потребовалось.

## Состояние после проверки

Контейнеры PostgreSQL и web оставлены работающими. Миграционный контейнер
сохранён в нормальном завершённом состоянии `Exited (0)`.
Веб-интерфейс доступен по http://127.0.0.1:8010/.
Рабочая БД — `pricewatch`; данные хранятся в `pricewatch_postgres_data`.
Порт PostgreSQL не опубликован на хост; веб-порт доступен только на loopback.

В новой рабочей БД пользователей пока нет. Для первого входа создайте администратора
командой `docker compose exec web python manage.py createsuperuser`.
Тестовые пользователи создавались только в отдельной тестовой БД Pytest.

Существующий контейнер другого проекта `open-webui` остался запущенным с прежними
идентификатором и образом. Удаление контейнеров, образов и томов не выполнялось.
Команды очистки Docker не использовались.

## История ограничения Docker и оставшиеся границы

При первой проверке Docker Desktop не смог запустить engine из-за ошибки
Inference manager (`dockerInference`). После восстановления Docker пользователем
это ограничение снято: сборка и фактический запуск Compose теперь подтверждены.

Для проверки PostgreSQL использован официальный переносимый PostgreSQL 17.11
от EDB: отдельный каталог `.tmp/pgdata-qa`, доступ только через 127.0.0.1:55432.
Это было временное проверочное окружение до запуска согласованной инфраструктуры Compose.
Временный пользователь браузерной проверки удалён; проверочные процессы остановлены.
Переносимые бинарники, проверочная БД и временные файлы после проверки удалены.

Linux-контейнер и Python 3.13 проверены непосредственно. GitHub Actions workflow
подготовлен; удалённый GitHub CI в этой сессии не запускался.
Окружение остаётся окружением локальной разработки первого этапа.

Порт 8000 занят существующим процессом; он не изменялся и не останавливался.
В локальном `.env` выбран `WEB_PORT=8010` и соответствующие CSRF origins.
